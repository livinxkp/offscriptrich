steal the craft, not the content

hey, it's KP. you commented BUILD, so here it is. the reel gave you the shape. this is the actual setup, the capture step that decides whether the whole thing works, the prompts i use word for word, and the parts it still gets wrong.

who this is for

you, if you've got a site you keep screenshotting because the type and the spacing are just right, and you want that level for your own thing. skip this if you want a one-click site builder — this is a terminal, and the first hour is admin.

why this matters

most people's websites look bad for one boring reason: they picked a template and then changed things at random. the sites you love aren't better because of taste you don't have. they're better because someone made a hundred small decisions about type scale, spacing and contrast and held them consistently across every page.

you can lift that decision set — the rhythm — without touching a single word, image or logo that belongs to them. that's the difference between inspiration and a rip-off, and it's also the difference between a site that looks expensive and one that doesn't.

what you need before you touch anything

ten minutes of setup, and one cost nobody mentions on camera.

Claude Code runs in a terminal, not a browser. you need a code editor to look at what it writes — VS Code is free and fine. and the part people leave out of the reels: Claude Code requires a paid Claude plan. Pro, Max, Team, Enterprise, or a Console account. the free claude.ai tier does not include it. know that before you start.

# macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# then check it landed
claude --version
claude doctor

now make an empty folder for your site, open a terminal inside it, and type claude. first thing you run is /init, which writes a CLAUDE.md file — a set of standing instructions it reads at the start of every session. that file is how you stop repeating yourself on day three.

capture the site properly

this is the step that decides the result. one screenshot is not enough input.

a full-page screenshot tells it the layout. it does not tell it the font stack, the exact greys, the line height or the spacing scale — and those are the things that make a site feel designed. so you give it both: the picture and the numbers.

  1. open the site, open devtools, open the command menu with Cmd+Shift+P (Mac) or Ctrl+Shift+P (Windows/Linux), type screenshot and take the full-size capture.
  2. take a second, tighter screenshot of just the hero and just one card or list item, so it can see the small stuff.
  3. then run this in the devtools console to pull the real computed values:
const rows = new Set();
for (const el of document.querySelectorAll('body *')) {
  if (!el.textContent.trim()) continue;
  const s = getComputedStyle(el);
  rows.add([
    el.tagName.toLowerCase(),
    s.fontFamily, s.fontSize, s.fontWeight, s.lineHeight,
    s.letterSpacing, s.color, s.backgroundColor
  ].join(' | '));
}
copy([...rows].slice(0, 250).join('\n'));

that copies a plain text dump of every distinct text style on the page straight to your clipboard. paste it into a file called reference-styles.txt in your project folder.

to get the images into Claude Code: drag and drop them into the window, or paste with Ctrl+V (Alt+V on Windows and WSL), or just give it the file path. don't use Cmd+V on Mac — that's your system paste, not the terminal's.

the rebuild prompt

vague brief, generic site. this one names the thing you actually want copied.

before you send it, press Shift+Tab until the status bar shows plan mode on, or start the session with claude --permission-mode plan. in plan mode it reads and proposes but writes nothing to disk until you approve. for a first build that's the difference between reviewing a plan and reviewing forty files.

I'm building my own site. Attached is a full-page screenshot of a
site whose design I want to learn from, two detail shots, and
@reference-styles.txt which is a dump of its real computed styles.

Rebuild the LAYOUT SYSTEM and VISUAL RHYTHM of that reference in
plain HTML and CSS. Specifically match:
- the type scale and the ratio between heading sizes
- line height and max line length for body text
- the vertical spacing scale between sections
- the grid: column count, gutter, max content width
- contrast levels between text, background and accent

Do NOT reuse any of their copy, images, logo, icons, brand name
or colour identity. Every word and every image is mine and is
listed in @content.md. Pick a different accent colour.

Build it as:
- index.html, one stylesheet, no framework, no build step
- CSS custom properties on :root for every colour and size, so I
  can retheme it by editing one block
- mobile first, working at 360px with no horizontal scroll
- semantic HTML, real heading order, alt text on every image

Before you write anything, list the type scale and spacing scale
you extracted as numbers, and tell me the three decisions you're
least sure about.

that last line is the highest-value sentence in the prompt. it forces the guesses into the open where you can correct them, instead of finding them baked into forty files an hour later.

make it check its own work

the self-correcting loop is the actual trick, and it needs a browser to work.

Claude Code can drive your browser. install the Claude in Chrome extension (v1.0.36 or higher), then start with claude --chrome, or run /chrome inside a session to connect and check status. it works in Chrome, Edge and other Chromium browsers — not in WSL. once it's connected, it can open your local build, screenshot it, and compare that screenshot to the reference you gave it.

Serve this folder locally and open it in the browser.
Take a screenshot of the full page and save it to disk.

Now compare that screenshot side by side with the reference
screenshot I gave you at the start. Give me a numbered list of
every difference you can see, most obvious first, in these
categories only: type size, weight, spacing, alignment, contrast.

Then fix the top five and repeat. Stop when your remaining list
is only things a normal person wouldn't notice.

run that two or three times. each pass it gets measurably closer. what it will not fix on its own is anything that moves — scroll-triggered reveals, parallax, hover transitions, sticky headers that shrink. it reads a still image, so motion is invisible to it. if you want those you have to describe them in words, one at a time, and accept a few rounds.

two commands worth knowing while you iterate: /diff shows you what changed in your working tree, and /rewind rolls code and conversation back to an earlier checkpoint when a pass makes things worse.

make it yours, not theirs

the last twenty percent is where it stops being someone else's site.

put your standing rules in CLAUDE.md at the project root so you never re-type them. it's read at the start of every session, so the corrections you make once stay made.

# CLAUDE.md

## what this project is
A personal site. Plain HTML and CSS. No framework, no build step.

## house rules
- All colours and sizes are CSS custom properties on :root.
  Never hardcode a hex or a px value anywhere else.
- Mobile first. Everything must work at 360px wide.
- Every image needs real alt text, not a filename.
- No lorem ipsum, ever. If you need copy, ask me for it.
- Don't add a library to solve something CSS already does.

## voice
Lowercase body text except proper nouns. Short sentences.
Second person. No exclamation marks.

## before you say you're done
Check heading order, check it at 360px, check colour contrast.

then swap in your own everything — your words, your photos, your name, a different accent colour, your own spacing where theirs doesn't fit what you're saying. what you keep is the discipline: one type scale, one spacing scale, held consistently. that's the part that was never theirs to begin with. build things that look like you can afford to care. that's Off-Script Rich.

good to know

  • animations are the wall, not a speed bump. it works from still images, so anything that only exists in motion — scroll reveals, easing curves, hover states — is invisible to it. budget two or three rounds of you describing them in words, or ship it static and add motion last.
  • fonts are the second wall. the computed styles dump gives you the exact font stack, which is useful and also frequently a licensed font you can't use. check whether it's on Google Fonts before you fall in love; if it isn't, ask for the closest open alternative by name and accept that the feel shifts slightly.
  • plan mode is not optional on the first build. without it you're reviewing forty finished files instead of one plan, and the fastest route to a site you don't understand is letting it write everything before you've agreed on the structure.
  • the boring bit is what makes it look expensive. ask it explicitly to check heading order, colour contrast and behaviour at 360px wide. it will not volunteer any of that, and every one of them is visible to a normal visitor even when they can't name it.
  • Chrome integration costs you context. enabling it by default loads browser tools into every session whether you need them or not. use the --chrome flag on the sessions where you're actually comparing screenshots, and leave it off the rest of the time.
