the notion content system

hey, it's KP. you commented SYSTEM, so here it is. here's the system from the reel: one database for every idea and script, the exact properties to add, the four views i use, and the agent prompt that plans the week. not sponsored, it's just how i run the page.

the database

make one full-page database called content. add these properties exactly:

propertytypewhat goes in it
titletitlethe on-screen hook, 3 to 6 words
statusstatusidea → scripted → filmed → edited → posted
pillarselectai / money / life (or yours)
referenceurlthe reel you're borrowing the topic from
keywordtextthe comment keyword
shoot datedatethe day it gets filmed
post datedatethe day it goes live
hooktextthe spoken first line
scripttextthe full script (or put it in the page body)
resultnumberviews after 7 days

the four views

  1. board by status. the pipeline at a glance.
  2. shoot list. a table filtered to status = scripted, sorted by pillar. this is what you open on shoot day.
  3. calendar by post date. so you can see gaps.
  4. winners. filtered to posted, sorted by result. what to make more of.

the agent prompt

on the business plan, open the notion agent and give it this:

Look at my "content" database.
1. Take every item with status "idea" and draft a hook and a script outline for each, written in a casual spoken voice.
2. Plan next week: pick [7] ideas, balanced across pillars, and set a shoot date of [day] and one post date per day from [date].
3. Change their status to "scripted".
4. Make a page called "shoot list [date]" listing them in shooting order with the hook for each.
Don't delete anything. Don't change items that are already filmed or posted.

on free or plus, you get the same system, you just fill in the plan yourself. that's Off-Script Rich: one page runs the week.

good to know

  • the agent needs the business plan. notion's pricing page lists the notion agent and ai meeting notes on business. free and plus get a limited trial.
  • check what it changed. agents can edit a lot of pages fast. look at the database after the first run before you trust it with the next one.
  • keep it to one database. the moment ideas live in three places, the system stops working.
