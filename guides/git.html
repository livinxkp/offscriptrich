fifty github tricks

hey, it's KP. you commented GIT, so here it is. the reel had four. these are all fifty, grouped so you can find the one you need: url swaps, line links, keyboard shortcuts, how to find good repos, and the markdown tricks that make you look like you've used this for years.

who this is for

you, if you open GitHub to grab a tool or read some code and always feel like you're doing it the slow way. skip it if you live in GitHub all day. you probably know most of these, though #6 and #18 surprise a lot of people.

the four from the reel

  1. swap github.com for gitdiagram.com: the repo draws itself as an interactive architecture diagram you can click through.
  2. swap hub for ingest (gitingest.com): the whole repo becomes one text digest you can paste into Claude or ChatGPT.
  3. swap github.com for gitmcp.io: you get an MCP server for that project's docs, so your AI assistant reads the real documentation instead of inventing functions.
  4. press . on any repo while signed in: it opens github.dev, VS Code in your browser, with search and extensions.

more url swaps

  1. press > (shift + .) instead: same browser editor, opened in a new tab so you keep the repo page.
  2. swap github.com for deepwiki.com: an AI-written wiki of the repo you can ask questions about.
  3. add .patch to a commit or pull request URL: the raw patch, in email format, with author and message.
  4. add .diff instead: just the diff, nothing else. good for pasting into an AI and asking what changed.
  5. add ?w=1 to any diff: hides whitespace-only changes, so a reformatted file stops looking like a rewrite.
  6. add ?plain=1 to a markdown file: shows the source with line numbers instead of the rendered page.
  7. go to /releases/latest: always lands on the newest release, so the link never goes stale.
  8. use /releases/latest/download/FILE: a permanent download link for an asset in the latest release.
  9. go to /archive/refs/heads/main.zip: downloads the main branch as a zip without cloning.
  10. type repo.new in your address bar: jumps straight to creating a new repository.
  11. type gist.new: jumps straight to a new gist, for snippets you want to share fast.

linking to exactly the right line

  1. add #L10 to a file URL: links to line 10 and highlights it.
  2. add #L10-L20: links to and highlights a range. or click one line number and shift-click another.
  3. press y on a file: swaps the URL to the exact commit, so your link keeps pointing at the same code after the file changes.
  4. open /blame/main/PATH: who last changed each line, and in which commit.
  5. open /commits/main/PATH: the full history of a single file.
  6. compare branches with /compare/main...feature: every difference between two branches on one page, with a button to open a pull request.
  7. compare across time with /compare/main@{1day}...main: what changed on main in the last day. swap the period for whatever you need.

keyboard shortcuts worth learning

  1. ?: shows every shortcut available on the page you're on.
  2. t: file finder. start typing a file name and jump straight to it.
  3. l: jump to a line number in the open file.
  4. b: opens blame view for the open file.
  5. s or /: focuses the search bar.
  6. ctrl + k or cmd + k: the command palette. search repos, files and commands from anywhere.
  7. g then c: go to the code tab.
  8. g then i: go to issues.
  9. g then p: go to pull requests.

finding good repos

  1. github.com/trending: what's gaining stars today. add /python and ?since=weekly to narrow it.
  2. github.com/topics/TOPIC: every repo tagged with a topic, sorted however you like.
  3. search with stars:>1000: filters out the abandoned experiments.
  4. search with pushed:>2026-01-01: only repos that have been touched this year.
  5. search with language:python: limit results to one language.
  6. in code search, use path: and repo:: e.g. path:SKILL.md finds every skill file on GitHub.
  7. in code search, wrap a pattern in slashes: /regex/ searches by regular expression.
  8. open /contribute on a repo: lists the issues maintainers flagged as good first contributions.

writing on github

  1. make a repo named exactly your username: its README becomes your profile page.
  2. > [!NOTE], [!TIP], [!WARNING]: coloured callout boxes in any markdown file, issue or comment.
  3. a ```mermaid code block: renders as a real diagram. flowcharts in plain text.
  4. - [ ] in an issue: a checklist people can tick.
  5. <details><summary>...: a collapsible section, so long logs don't swamp the page.
  6. "closes #12" in a pull request description: merging the PR closes issue 12 automatically.
  7. a ```suggestion block in a review: proposes an exact edit the author can accept with one click.
  8. /issues/new?title=...&body=...: a link that opens a pre-filled issue. great for bug-report buttons.

and two more

  1. github.com/USERNAME.png: anyone's profile picture as a direct image link.
  2. watch, then custom, then releases only: get notified when a tool ships a new version, without every comment.
  3. /pulse on any repo: a one-week summary of what got merged, opened and closed.

the three to use today

  1. gitingest any repo you're curious about, paste the digest into Claude and ask "explain this like i'm new to it".
  2. press y before you share any code link, so it doesn't break next week.
  3. press t instead of clicking through folders.

good to know

  • the swap sites are third parties. gitdiagram, gitingest, gitmcp and deepwiki are separate projects, not GitHub. they only work on public repos, and you shouldn't point them at anything private.
  • shortcuts depend on the page. some only work on a file view, some only when you're signed in. press ? to see what's live where you are.
  • search syntax splits in two. repo search and code search use slightly different filters. stars: and pushed: are repo search, path: and regex are code search.
